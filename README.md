# Dymok: сайт, каталог, склад і замовлення

У Dymok інтегровано модуль із `device-admin.zip`: керування категоріями, довільними характеристиками, товарами, фото та знижками. Вітрина, кошик, склад і замовлення використовують спільний каталог SQLite. Наявний дизайн вітрини збережено.

## Швидкий запуск

Потрібні Python 3.9+ та інтернет для першого встановлення залежностей.

- **Mac:** відкрийте `start.command`. Якщо macOS не дозволяє його відкрити, запустіть у терміналі в цій папці: `bash start.command`.
- **Windows:** відкрийте `start.bat`.

Скрипти створять локальне середовище `.venv`, встановлять Flask і Pillow та запустять сервер.

Ручний запуск на Mac/Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py
```

На Windows активація: `.venv\Scripts\activate`.

- Сайт: **http://localhost:8000/**
- Склад, замовлення, зміна пароля: **http://localhost:8000/admin/**
- Товари, категорії, фото, знижки: **http://localhost:8000/admin/catalog/**

Логін і пароль із наданої бази збережені. Вхід спільний для обох розділів адмінки. Якщо бази немає, сервер запропонує створити адміністратора в терміналі. Відновлення доступу: `python server.py --set-password`.

Як і раніше, можна задати `admin_username` та `admin_password` у `config.json`: під час запуску пароль буде застосований та видалений із файлу. Пароль має містити щонайменше 10 символів. Файл конфігурації не публічний.

## Керування каталогом

1. Увійдіть в адмінку й натисніть **«Каталог і знижки»**.
2. Створіть категорію або відредагуйте наявну. Для кожної характеристики задайте сталий ключ латиницею, назву та обов’язковість. Максимум 40 полів; значення до 500 символів.
3. Створіть товар: назва, бренд, варіант/смак/колір, категорія, опис, ціна, знижка, характеристики та фото.
4. У списку товарів доступні пошук, фільтр за категорією, пагінація, редагування та видалення.
5. Кількість товару задавайте в розділі **«Склад»**. Новий товар спочатку має режим «без обліку».

Під час зміни категорії незбережені характеристики запам’ятовуються окремо для кожної категорії в межах відкритого редактора. Не можна видалити категорію, яка містить товари, або змінити схему так, щоб вона стала несумісною з наявними даними.

Фото: справжні JPEG/PNG/WebP, до 5 МіБ та 20 мегапікселів. Сервер перевіряє зображення, виправляє орієнтацію, зменшує до 2400×2400 і зберігає WebP під випадковою назвою. Фото можна замінити або видалити. Початкові зовнішні фото збережені до заміни/видалення.

Вітрина показує початкову ціну, відсоток знижки та кінцеву ціну. У вікні товару відображаються опис і всі характеристики. Нові категорії автоматично з’являються в каталозі. Відкрита вітрина оновлює каталог кожні 60 секунд і після повернення до вкладки; під час відкритого вікна товару/оформлення оновлення каталогу відкладається. Перезавантаження сторінки завжди бере свіжі дані з бази.

Ціни товарів та підсумки замовлень рахуються в цілих копійках. Знижка — 0–100%, до двох десяткових знаків; округлення `ROUND_HALF_UP`. Сервер сам визначає ціну замовлення з бази, ігноруючи ціни покупця. Текст для Telegram та історія отримують підтверджені сервером назви й суми. Прийняття замовлення і списання залишків відбуваються в одній транзакції; скасування повертає залишок лише один раз.

## Дані та перенесення

Під час першого запуску нова схема додається автоматично. Усі **161 товар і 4 категорії** переносяться з початкового каталогу зі збереженням ID. Дані адміністратора, залишки та замовлення не видаляються. Повторний запуск не перезаписує каталог і не повертає видалені товари. Нові ID не повторно використовуються після видалення, тому старі замовлення й кошики не можуть вказати на інший товар.

Перед додаванням каталогу створюється `data/dymok-before-catalog.sqlite3` через SQLite Backup API, включно з даними WAL. У готовому архіві міграцію вже застосовано; резервна копія оригінальної бази включена.

Зберігайте резервні копії:

- `data/dymok.db` — каталог, залишки, замовлення, хеш пароля й сесії;
- `data/media/` — завантажені фото;
- `data/session.key` — постійний секрет CSRF-сесій, створюється автоматично.

Для копіювання бази під час роботи використовуйте SQLite Backup API, або зупиніть сервер перед копіюванням. Не копіюйте лише `.db`, коли актуальні записи можуть залишатися у WAL.

`catalog-seed.json` та `assets/js/01-products.js` — початкові знімки. Після перенесення редагуйте товари через адмінку: файли не перезаписують каталог у базі. Відкриття `index.html` як файлу лишається статичним переглядом початкового асортименту; для актуального каталогу й адмінки потрібен Python-сервер.

## Основні файли

| Файл | Призначення |
|---|---|
| `server.py` | Запуск, авторизація, склад, замовлення та безпечна видача файлів |
| `catalog.py` | Flask API каталогу, валідація, CSRF, фото |
| `catalog_store.py` | Міграція, початковий імпорт, спільні дані для вітрини |

| `legacy_wsgi.py` | Підключення наявних маршрутів складу/замовлень до Flask |
| `admin/` | Склад і замовлення |
| `admin/catalog/` | Редактор каталогу |
| `src/`, `build.py` | HTML-компоненти та збирання `index.html` |
| `tests/` | API, інтеграція й міграції на тимчасових базах |

## API

Публічні: `GET /api/catalog` — товари й категорії для вітрини; `GET /api/catalog.js` — початкове завантаження вітрини; `GET /media/<filename>` — фото. Наявні API залишків, замовлень та адміністратора збережені.

Закриті для адміністратора:

| Метод | Маршрут | Дія |
|---|---|---|
| GET | `/api/session` | Стан спільного входу та CSRF-токен |
| POST | `/api/login`, `/api/logout` | Вхід / вихід |
| GET / POST | `/api/categories` | Список / створення категорії |
| GET / PUT / DELETE | `/api/categories/<id>` | Категорія |
| GET / POST | `/api/products` | Пошук і пагінація / створення товару |
| GET / PUT / DELETE | `/api/products/<id>` | Товар |

Категорії передаються JSON: `name`, `attribute_schema` (масив `{key,label,required}`). Для змін передавайте `X-CSRF-Token` із `/api/session`, для входу використовуйте новий токен із відповіді `/api/login`.

Товари передаються через `multipart/form-data`: `name`, `category_id`, `price`, `discount_percentage`, `attributes` (JSON-об’єкт), `description`, `brand`, `spec`, необов’язковий `image`, `remove_image=0|1`. PUT замінює весь набір полів, а не виконує PATCH. Не задавайте `Content-Type` вручну при використанні браузерного FormData.

Суми `original_price`, `final_price`, `discount_percentage` у редакторському API — десяткові рядки. Пошук: `q`, `category_id`, `page`, `limit` (до 100). Успіх: 201 / 200 / 204; помилки JSON `{error: "..."}`.

## Перевірки та розгортання

```sh
python -m unittest discover -s tests -v
python build.py
```

Результати перевірок і межі тестування наведено у `QA.md`.

Для WSGI-хостингу використовуйте `wsgi_app:application` після встановлення залежностей у відповідне Python-середовище. Для Linux можна встановити Gunicorn окремо й запустити `gunicorn --bind 127.0.0.1:8000 wsgi_app:application`. Адміністратора підготуйте через `server.py` або `config.json`; WSGI-запуск без адміністратора підкаже спосіб налаштування.

Для публічного сервера потрібні HTTPS, `COOKIE_SECURE=1`, постійний диск для бази й фото та резервні копії. `TRUST_PROXY=1` задавайте лише за довіреним reverse proxy, який очищує клієнтські forwarding-заголовки. Ліміт тіла запиту проксі має бути не менше 6 МіБ. Вбудований сервер — для локального запуску. Статичний хостинг не підтримує адмінку й SQLite.
