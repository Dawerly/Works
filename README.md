# Структура сайту

Оновлена копія розділеного сайту. Виправлено загальну навігацію, доступність, мобільну шапку та вікно перевірки віку. Додано кнопку повернення вгору й технічне пояснення про локальні дані.

Результати й межі перевірок — у `QA.md`, перелік змін — у `CHANGELOG.md`.

## Сервер, база даних і адмін-панель

Для обліку залишків і замовлень потрібен сервер: `server.py` (лише Python 3.9+, без встановлення пакетів).

1. Запустіть: `python3 server.py`. Windows: подвійний клік по `start.bat`. Mac: подвійний клік по `start.command` (якщо macOS не відкриває: правий клік → Відкрити; або в Терміналі `cd` у папку й `python3 server.py`).
2. Логін і пароль адміна задайте одним зі способів:
   - **у файлі `config.json`** (поруч із `server.py`): впишіть `admin_username` і `admin_password`, збережіть, запустіть сервер. Він застосує дані й **сам витре пароль із файлу**; у базі лишається лише хеш. Так само можна змінити пароль пізніше;
   - або введіть у терміналі при першому запуску.
   Пароль від 10 символів. Не вписуйте пароль у файли в `admin/` чи `assets/` — вони публічні. `config.json` публічним не є.
3. Сайт: http://localhost:8000/ · Адмінка: http://localhost:8000/admin/
4. Дані (залишки, замовлення, хеш пароля) лежать у `data/dymok.db`. **Робіть копії цього файлу.**

Що вміє адмінка: залишки по кожному товару (поле, +/−, масове встановлення, «без обліку»), замовлення зі статусами та часом доставки для клієнта (клієнт бачить його в кабінеті), скасування замовлення повертає товар на склад, зміна пароля.

Залишки: товар без запису в базі = «без обліку» (завжди доступний). Щойно ви вписали число — воно списується з кожним замовленням, а на 0 товар стає «Немає в наявності». Ціни сервер бере з `assets/js/01-products.js`, а не з браузера покупця.

Забули пароль: `python3 server.py --set-password` на комп'ютері, де працює сервер.

Для інтернету потрібен хостинг з Python і HTTPS (VPS, PythonAnywhere, Render тощо). Запускайте з `HOST=0.0.0.0`, за зворотним проксі додайте `TRUST_PROXY=1`. Звичайний статичний хостинг (GitHub Pages, Netlify без функцій) базу не підтримує — сайт там працюватиме, як раніше, без обліку залишків і адмінки.

## Як відкрити лише сторінку (без бази)

1. Розпакуйте весь архів в одну папку.
2. Відкрийте `index.html` у браузері.

Для перегляду не потрібні встановлення пакетів, Node.js або локальний сервер. Google Fonts і зовнішні зображення завантажуються з інтернету, як у вихідному файлі.

## Де що лежить

```text
dymok-site-updated/
├── index.html                 Готова сторінка для відкриття
├── logo.png                   Логотип
├── README.md                  Ця інструкція
├── build.py                   Збирання сторінки з HTML-фрагментів
├── server.py                  Сервер: сайт, база даних, API, вхід адміна
├── config.json                Тут можна задати логін і пароль адміна
├── start.bat                  Запуск сервера у Windows
├── start.command              Запуск сервера на Mac
├── admin/                     Адмін-панель (/admin/)
├── data/                      Створюється сама: dymok.db (не видаляйте!)
├── assets/
│   ├── css/                   Стилі, розділені за блоками
│   └── js/                    JavaScript, розділений за призначенням
└── src/
    ├── index.template.html    Каркас документа та підключення
    ├── manifest.json          Порядок підключення CSS і JavaScript
    ├── pages/                 Головна, каталог і кабінет
    └── components/            Шапка, підвал, навігація та окремі вікна
```

## Як редагувати

- **CSS або JavaScript:** відкрийте відповідний файл в `assets/`, збережіть і оновіть сторінку браузера. Збирання не потрібне.
- **Тексти та HTML-розмітка:** редагуйте відповідний фрагмент у `src/pages/` чи `src/components/`, потім запустіть з папки сайту:

  ```sh
  python3 build.py
  ```

  У Windows команда може бути `py build.py`. Потрібен Python 3; додаткових бібліотек немає.
- **Підключення файлів:** список і порядок містяться у `src/manifest.json`.

`index.html` уже зібраний. Його можна редагувати напряму, але наступний запуск `build.py` перезапише такі правки. Для постійних змін розмітки використовуйте файли в `src/`.

## Що важливо зберегти

- Нумерація CSS та JavaScript відповідає вихідному порядку. Вона зберігає каскад стилів і залежності коду. Не переставляйте файли довільно.
- JavaScript підключено як звичайні скрипти з `defer`, без `type="module"`. Частини використовують спільні змінні й функції, як у вихідному документі.
- Атрибути `id`, `data-*` та назви CSS-класів використовуються обробниками.
- Локальні атрибути `style` та обробники помилки зображень збережено, щоб не змінювати поведінку під час розділення.
- Частина правил теми навмисно перевизначає попередні стилі; їхній порядок збережено.
- `logo.png` взято з попередньої папки цього сайту `Desktop/Works`, оскільки біля переданого HTML у Downloads його не було.

Вихідний файл у Downloads і попередній ZIP не змінено. Це окрема оновлена копія.

## Повторення перевірок

Статичні перевірки запускаються без додаткових пакетів:

```sh
python3 tests/static_checks.py
```

Браузерні перевірки — додатковий інструмент для розробника. Потрібні Node.js, пакет `playwright` і Chromium або Chrome:

```sh
node tests/browser-checks.cjs
```

За потреби задайте `PLAYWRIGHT_MODULE` як шлях до встановленого пакета, а `CHROME_PATH` — до браузера. Ці залежності потрібні лише для тестів. Для відкриття готового сайту вони не потрібні.

Браузерні тести використовують тимчасовий чистий профіль і локальний сервер, підміняють зовнішні відповіді та не виконують реальних транзакцій. JSON-звіти й знімки екрана знаходяться в `tests/`.
